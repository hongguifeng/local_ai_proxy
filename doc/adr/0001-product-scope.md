# ADR-0001: Node.js 首发产品边界

- 状态：已接受
- 日期：2026-07-10
- 决策阶段：0.1

## 背景

Python 版本是本地开发工具原型。Node.js 重构需要先固定首发支持范围、数据迁移、安全边界和容量默认值，否则打包、配置 schema、管理 API 与 UI 会产生互相冲突的假设。

## 候选方案

1. 首发即覆盖所有桌面平台、远程管理和完整历史兼容。
2. 先交付明确的平台与本地使用边界，通过一次性迁移保留用户数据。
3. 完全不迁移数据，以全新应用发布。

## 决策

- 正式支持 Windows 10/11 x64 和主流 glibc Linux x64。macOS、Windows ARM64、Linux ARM64 暂不承诺，待原生 SQLite addon、发布 runner 和用户需求均可验证后重新评估。
- Windows 首发产物是包含固定 Node runtime、应用文件、静态资源、migration 和 native addon 的便携目录；不要求单文件 exe。
- 提供一次性迁移工具处理 Python 版 `proxies.json` 和 `traffic.db`。迁移前备份、可重复检测，失败不修改唯一源数据；不做长期双写。
- 管理服务默认仅绑定 loopback。非 loopback 仅允许在显式 `--allow-remote-admin` 且配置认证 token 时启动；无认证的远程管理明确禁止。
- request 和 response 原始内容的默认捕获上限分别为 8 MiB，硬上限分别为 64 MiB；超限继续转发并记录截断。request 转发 body 的独立默认上限为 32 MiB。
- 日志默认保留 30 天；可关闭或调整，并同时受后续磁盘低水位保护约束。
- 第一阶段复用现有 UI 的工作流和布局，迁移到 Vite + TypeScript，但不引入前端框架。状态复杂度或组件复用需求显著增长时再通过 ADR 评估框架。
- 首个正式版本不集成操作系统凭据存储。secret 可保存在本地配置，但 API 不回显、日志不记录，并限制文件权限。

## 原因

该范围覆盖现有主要用户场景，同时把 native addon 打包、跨架构验证、远程管理安全和 UI 框架迁移控制在可独立验收的边界内。一次性迁移比运行期兼容和双写更容易验证，也符合项目不保留旧内部 API 的约束。

## 影响

- CI 必须覆盖 Windows x64 和 Linux x64。
- 发布说明必须明确非支持平台和便携目录形式。
- 配置 schema 必须区分转发 body 上限与日志捕获上限。
- retention、远程 admin 和迁移工具在正式切换前必须完成。

## 重新评估条件

- macOS 或 ARM64 成为明确发布需求，并且 native addon 有可重复构建和 smoke test。
- 单文件分发成为硬性渠道要求。
- 远程/团队使用成为主要场景，需要更完整的身份认证和 TLS 终止。
- UI 状态复杂度使无框架实现的测试或维护成本明显上升。
