# ADR-015：单请求总结与任务简介共用执行过程合同

> 状态：决策记录
> 权威性：记录单请求总结的输出与缓存合同调整。
> 更新条件：本决策被替代时增加后继 ADR 引用。

## 背景

单请求智能总结原来接受模型的 `title`、`segments`、`decisions`、`issues` 及任意扩展键。任务简介已经使用服务端编号事件、证据校验和阶段弹窗。用户要求单请求总结也使用当前提示词和界面，两种答案合同继续分开会导致语义和展示漂移。

## 决策

1. 单请求总结与任务简介使用同一个事件规范化器、`TASK_BRIEF_INSTRUCTION`、提示词版本和答案解析器。
2. 单请求来源固定为选中 record；任务简介继续选择任务最新已完成请求。缓存按各自身份独立保存。
3. `history_summaries.summary_json` 保存服务端校验后的执行过程 DTO，包括时间线、来源事件、环境和生成元信息。API 只序列化声明字段，不保留模型随意添加的键。
4. 旧 `segments` 缓存不迁移、不伪造阶段；GET 返回空，下一次用户点击时重新生成。保留旧数据库行及列表成功标记，生成失败不删除旧行。
5. 请求弹窗复用现有时间线组件和样式，保留复制及重新生成。异步完成必须核对请求身份，关闭后不强制重开。
6. 总结更新缓存时同步更新 `prompt_version`，确保旧格式重生成后记录实际使用的版本。

## 替代方案与影响

保留旧解析器、把 `segments` 映射成阶段能继续显示旧缓存，但旧数据没有当前编号事件及证据校验，无法证明引用对应关系。单独复制提示词和 CSS 会产生两份维护来源。因此采用共享合同，旧内容由用户按需重生成。

不新增数据库列，不改变原始请求、响应、代理转发或用户模型配置。执行过程语义见[任务执行过程设计](../../design/accepted/task-execution-summary.md)，请求接入见[单请求设计](../../design/accepted/history-summary.md)。

## 验证依据

服务测试覆盖所选请求与最新请求的区别、旧缓存读空、版本更新、越界证据保留缓存和并发隔离；真实 HTTP 测试证明新 DTO 落库与读回一致；浏览器测试验证阶段展示、证据跳转、缓存复用和迟到结果。交付结果记录在[执行计划](../../plans/archive/record-summary-timeline.md)。
