# 控制台功能行为

> 状态：当前
> 权威性：管理控制台中这几项功能的用户可见交互行为。
> 更新条件：这几项功能的界面入口、成功或失败表现、回退规则或计数口径变化时更新。

README 只说产品有什么能力，这份文档说同一批功能在界面上具体怎么表现：转发地址测试与模型列表、上游指标看板、模型价格自动填充、历史列表与任务明细面板的读法，以及使用统计的几条计数口径。产品总览、配置语义和代理数据面行为的唯一权威是[当前产品行为](product.md)，请求速度的测量口径写在该文档的“速度指标的测量口径”一节；负载均衡与任务路由的语义见[负载均衡设计](../design/accepted/load-balancing.md)和[task 路由设计](../design/active/task-routing.md)；颜色、尺寸和画面内容见[UI 视觉基线](contracts/ui-visual-baseline.md)；实现位置和验证命令见[当前架构](architecture.md)。本文不复述这些材料里已经写过的同一事实，只补控制台的交互细节，并在每节末尾指出钉住它的测试。

## 1. 转发地址测试与模型列表

### 1.1 连通性测试

转发地址卡片底部的 **Test / 测试** 按钮向该地址发一次最小 ping 请求，按卡片上选的 API 类型走 OpenAI Chat、Responses 或 Anthropic Messages。这次请求不经过代理监听器，也不写进历史。结果按成功或失败写在弹窗里：上游返回错误状态时，服务端的错误细节同时进提示条；地址连不上时写成失败。

### 1.2 拉取模型列表

弹窗里的 **拉取模型列表 / Fetch models** 按钮直接向该转发地址取模型列表，不经过代理监听器。请求顺序与鉴权如下：

1. 先请求 OpenAI 风格的 `{base}/models`。
2. 这一路返回 404 或 405 时，改请求 Anthropic 风格的 `/v1/models`（基路径末尾的 `/v1` 先去掉），并额外带 `anthropic-version`。
3. API Key 同时按 `Authorization: Bearer` 和 `x-api-key` 发出，两种协议都能接受。
4. 中间任何一路返回其它状态码就中止，并把“上游对某路径回答了 NNN”写成失败原因；两路都是 404/405 时写成“该地址没有模型列表接口”。

界面表现：

- 成功时模型 ID 下拉的候选换成上游真实返回的 ID，并自动填入第一个；当前已经输入的值在这份列表里就保持不变。提示行写出条数和用时。
- 下拉右侧的 ▾ 展开整份拉到的列表；开始输入后只保留包含所输内容的项，点一项即填入该 ID。
- 失败时下拉恢复内置的默认候选，模型 ID 保留用户输入的内容，失败原因同时写在提示行和提示条里；此时手工输入的模型名仍然可用。

拉到的列表只在当前弹窗内有效：关闭或重新打开就回到默认候选，不写进模型映射，也不改动已保存的配置。上游返回超过 1000 个 ID 时只保留前 1000 个并在提示里注明；单个 ID 超过 4096 个字符的直接丢掉。

测试：`test-node/proxy/target-models.test.ts`、`test-node/ui/admin-ui-proxy.test.ts`。

## 2. 上游指标看板

转发地址卡片底部的 **Metrics / 指标** 按钮由管理端替浏览器请求上游 `GET /metrics`（Prometheus exposition 格式），因此不受浏览器 CORS 限制。基路径下没有 `/metrics` 时自动改试主机根路径——vLLM、SGLang 等引擎通常在根路径暴露指标。响应超过 1 MiB 时截断，并在界面上注明。

### 2.1 vLLM 看板

exposition 里出现 `vllm:` 指标时默认展示看板，六个区块按固定顺序排列：引擎状态、实时负载、缓存与投机解码、Token 吞吐、进程资源、延迟分布。**延迟分布固定排在最后**，不随数据变化。看板内容包括：

- 引擎状态：模型名、运行时长和 sleep 模式。
- 实时负载：运行中与排队请求数、KV 显存占用条、抢占次数。
- 缓存与投机解码：前缀命中率、投机解码接受率、缓存配置。
- Token 吞吐：累计输入与输出、平均请求长度、估算解码速度、输入 token 的来源堆叠条、结束原因标签。
- 进程资源：内存、CPU、文件描述符。
- 延迟分布：TTFT、ITL、排队、prefill、decode 和端到端的 p50/p95/p99，由 histogram 桶插值估算，同时给出均值和桶分布条形图；这些数值是近似值，不是引擎的精确分位数。

悬停卡片或面板可以读该指标的含义说明。

### 2.2 自动刷新

工具栏的“自动刷新”下拉有 关闭 / 5 / 10 / 30 / 60 秒 五个选择。选中间隔后按间隔重新拉取并就地重新渲染：保留已展开的指标族、筛选条件和当前滚动位置，不闪加载状态，旁边有逐秒倒计时。弹窗关闭时定时器自动停止，重新打开后按下拉的选择恢复；手动刷新也会恢复滚动位置。

### 2.3 回退到全部指标

exposition 里没有 `vllm:` 指标时自动改用最简单的“全部指标”列表：按指标族折叠、按名称筛选、可以展开原始文本。地址连不上时写出失败原因。

测试：`test-node/proxy/target-metrics.test.ts`、`test-node/ui/admin-ui-proxy.test.ts`。

## 3. 模型价格自动填充

“模型价格”里的 **拉取模型并填价 / Fetch models & fill prices** 按钮做三件事：向上游取一次模型列表（取法同 1.2 节）、在 [models.dev](https://models.dev) 目录里查每个模型的价格、按填入的汇率（`1` 等于美元原价）换算后写成价格规则。

- 取到的模型列表只用于定价，不写进模型映射。
- 已有的价格规则不改动；目录里没有价格的模型只在提示里列出。
- 同一个模型 ID 被多家 provider 列出时，优先取名字与上游主机能对上的那家。
- 价格换算后写不到六位小数的模型按“未匹配”处理，不会因为一个存不下的数字让整批失败。
- models.dev 目录在内存里缓存 24 小时；缓存过期后重新拉取，拉取失败时仍用手里这份旧目录。

注意：上游 `/models` 通常不返回价格（DeepSeek 就是如此），这里的数字来自 models.dev 这个第三方目录，可能过期（例如 DeepSeek 只列空闲时段价）。填入之后、保存之前，请对照厂商官方价目表核对一遍。

测试：`test-node/pricing/model-catalog.test.ts`、`test-node/admin/model-prices-import.test.ts`、`test-node/ui/admin-ui-proxy.test.ts`。

## 4. 历史列表与任务明细面板

### 4.1 两个入口各管一件事

任务卡片头部（包括键盘上的 Enter 和空格）只打开“任务明细”面板，不会展开或收起该任务的请求列表；展开与收起二级列表的唯一入口是控制列第三行的三角形按钮。二级列表在展开时才按需加载该任务的请求。

### 4.2 两种耗时

面板里的“任务总耗时”（`total_request_ms`）是墙钟时间：第一个请求的开始到最后一个请求的结束，中间的请求间隔也算进去；任一端缺失就留空。“请求总耗时”（`active_request_ms`）是各请求自身耗时之和，不含请求之间的间隔。两者同时显示，前者回答“这件事办了多久”，后者回答“请求本身花了多久”。

### 4.3 大请求体为什么点开就能看见

请求和响应 JSON 并排显示，支持展开、折叠、换行、格式化和复制。折叠的节点先只显示摘要，展开时才生成子节点；鼠标悬停在请求行上（停留一小段时间）就预取该条详情，按下指针时立刻开始取，滚动时也会预填充视口附近的行，所以几 MB 的请求点开几乎立即可见。切换请求后到达的迟到结果不会覆盖当前请求的内容。

### 4.4 未计价不等于免费

缺少可靠用量或价格规则的记录标为“未计价”，不会当作免费：任务卡片、任务明细和统计都按这个规则显示未计价数量，并给出原因。任务明细面板按输入、输出、缓存读、缓存写四个分区列出用量与费用，合计行不填底色；三张逐请求趋势图（费用、token 总量、token 输出）各在自己的最高点旁边直接标出该点的具体数值，费用图与 token 输出图另有一条逐请求均值的虚线。计费模型分组展开后显示单价和费用占比。

### 4.5 单请求智能总结

**智能总结** 按钮把选中的那条请求交给配置的总结模型，与任务简介共用同一套事件规范化、提示词、证据校验和弹窗组件：弹窗显示概述、环境信息、执行位置轨道、目标、结果、思路和缺口，证据编号可以跳回原始事件。读取缓存不产生模型调用，同请求并发生成返回 409，生成失败不覆盖旧缓存。已经生成过总结的请求在列表里带金色星标。旧的分段（`segments`）格式不迁移：读取返回空，点按钮时重新生成新格式，旧的星标保留。语义细节见 [ADR-015](../decisions/adr/015-record-execution-summary.md)。

任务简介、环境事实标签和它的缓存规则由[当前产品行为](product.md) 与[任务简介设计](../design/accepted/task-brief.md) 负责，本文不重复。

### 4.6 导出与清理是三枚不同的按钮

- **导出** 导出整个历史，不挑任务：`GET /api/logs/export` 把每个日志根里的每个任务写成 ZIP 里的一目录，任务根有一 `index.md`（可读的任务索引），每条请求有自己的 `summary.md`、`request.json`、`response.json` 和 `pricing.json`。浏览器拿到的文件叫 `llm-proxy-logs.zip`。
- **清理选中** 删除勾选的任务及其请求记录（`POST /api/logs/cleanup`）。没有勾选任何任务时只提示“请先选择要清理的任务”，不会误删。
- **清理单请求** 沿当前搜索分页扫描整个列表，把所有只含一条请求的任务删掉；这一枚不读勾选框。

测试：`test-node/ui/admin-ui-history.test.ts`、`test-node/ui/admin-ui-json-pane-refresh.test.ts`。

## 5. 使用统计的几条口径

### 5.1 任务计数

只有当一个任务在所选范围内有超过 5 条**已计价**请求时，才计入任务总数；概览、分布行和趋势桶用同一条规则。未计价请求不进任何总量。

### 5.2 未计价请求

缺少用量或价格的请求标为“未计价”，不会当作免费，界面给出可查明细的入口。只有价格缺失、用量完整时，单条明细仍列出上游返回的四类 token，金额为空；这类请求不进用量统计的总量。

### 5.3 “其他” 合并

分布环形图和按模型、按转发地址堆叠的趋势图，在分类超过六项时按当前指标排序，把末尾累计占比仍严格小于 10% 的分类合并成“其他”（英文 `Other`）；趋势的每个时间桶用同一套分类。概览里的分布另有“只留前 9 名，其余合并”的显示规则，见[使用统计设计](../design/accepted/usage-statistics.md)。

### 5.4 纵轴刻度与数字单位

统计页的 **导出** 把当前筛选范围写成 CSV（`GET /api/usage-statistics/export`，带 BOM 以便电子表格认出 UTF-8）：一行一个时间桶，列是 `bucket,requests,tasks,input,output,cache_read,cache_write,cost,unpriced`。

趋势图的纵轴上界取“第一个能刚好包住最高柱形的整齐刻度步长的整数倍”，不是把峰值直接抬到更大的整数上限，所以柱形会填满绘图区而不会在顶部留出大片空白。步长候选是同一十进位上的 1、2、2.5、5、10；费用指标的刻度带货币符号，token 指标用压缩单位。Token 数字在英文界面上用 K/M/B，在中文界面上用万/亿。

测试：`test-node/ui/admin-ui-statistics.test.ts`。
