# Windows 发布签名

> 状态：运维手册
> 权威性：Windows 发布是否签名以及未来启用签名时的操作边界。
> 更新条件：证书、发布工作流、签名工具或组织策略变化时更新。

## 当前策略

当前发布产物不执行代码签名。发布流程生成 portable EXE、安装包和 CLI ZIP；发布只从 `v*` tag 触发。签名未启用前，不要在本地凭空加入证书路径、秘密或签名步骤。

## 未来启用时

启用签名前必须明确：

- 证书由哪里托管，私钥如何进入 GitHub Actions，日志如何避免泄露。
- 签名发生在 electron-builder 之前还是之后，以及如何验证 exe、安装包和 ZIP 内文件。
- 本地开发、CI 和发布环境使用的工具版本与时间戳服务器。
- 签名失败是阻止发布还是保留未签名产物。

实现后新增独立的签名验收报告和 workflow 测试，不把“存在证书变量”当成签名成功。详细打包与 artifact 检查见 `packaging-smoke` skill。
