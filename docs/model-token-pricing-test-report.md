# 模型 Token 定价测试报告

执行日期：2026-09-11。环境为本仓库 Windows 本地开发机（Node 24、SQLite/better-sqlite3），所有数据均由本地 fixture 生成，不调用付费上游。

## 覆盖范围

- 配置、最终上游模型冻结、JSON/SSE usage 标准化、BigInt 金额、SQLite 持久化、任务聚合、管理 API、浏览器列表/详情和导出分别由 `test-node/pricing/`、`test-node/persistence/`、`test-node/maintenance/`、`test-node/admin/` 和 `test-node/ui/` 覆盖。
- 用户示例的四桶用量 `1500 / 1000 / 1000 / 500` 与 `5 / 30 / 0.5 / 6.25` 单价的固定断言为 `41125000` 纳元（`¥0.0411` 显示）；三请求 task 固定断言为 `¥0.0428` 显示。
- 代理流与普通 JSON 的用量采集、协议错误/中断、旧库迁移、价格变更后快照保持、不同 target 的 task 边界，以及 `pricing.json` 导出均在对应自动化回归中验证。

## 大数据性能回归

执行命令：`npx tsx scripts/pricing_benchmark.ts`。

夹具创建 4 个独立日志目录，共 10,000 条已计价 record；每目录有一个 2,500 条 record 的 task。随后对普通列表、搜索列表和单 task 费用明细各连续执行 5 次，记录中位数：

| 操作 | 中位数（ms） |
| --- | ---: |
| 多目录 task 列表（含费用批量聚合） | 90.19 |
| 多目录搜索列表（含 preview 与费用） | 123.34 |
| 2,500 条 task 的费用明细 | 23.61 |

费用列表只读取摘要/快照列，不读取请求或响应正文；task 明细按单 task 聚合，未做每条请求的前端或 N+1 查询。多目录路径现在也传递批量费用聚合，避免只在单目录显示金额。这个仓库此前没有可复现、同结构的“无费用”10k 基线，因此不把上述值伪称为百分比退化；后续性能比较应以此夹具和同机中位数为基线，并调查超过 20% 的回归。

## 结论

长 SSE 的 usage 观察器维持单事件上限，金额使用 BigInt/十进制字符串；压力夹具的内存不随正文长度保存。自动化回归和项目最终检查的实际命令、结果记录在开发 TODO 中。
