# Probing the admin UI without rebuilding

These traps were learned in this repository and moved here verbatim from `AGENTS.md`;
nothing was paraphrased.

- Verifying a `src/admin/static` change against the user's already-running portable instance is faster than rebuilding: read its admin port from `D:\Portable Program\llm_proxy\llm-proxy.json`, then have Playwright intercept `**/static/app.js` and serve the _instance's own_ script with the same patch applied to it. Serving the working tree's `app.js` on an older page dies at load (the page injects globals the newer script reads, e.g. `__SUGGESTED_STRIP_REQUEST_FIELDS__`) so nothing renders and the probe just times out. On real data, measure the tallest `.trend-bar` height against the 200 px plot instead of eyeballing screenshots — pixel diffing cannot tell a tight axis from a padded one. For a CSS change, prove cascade-neutrality with a computed-style digest over `document.querySelectorAll("*")` on that live instance, compared as the _set_ of style signatures rather than element-by-element index: the instance keeps ingesting records, so the two loads have different element counts and index alignment is meaningless, while a real cascade change makes a signature disappear and another appear and data drift only shifts how many elements share one signature. Sample longhands (expand `padding`/`margin`/`border`/`background`/`font`/`flex`/`outline`/`text-decoration`) because a digest keyed on the names the file spells out misses exactly what shorthands control, and sample `getComputedStyle(el, "::before")` separately — pseudo-elements are invisible to the plain call. Always falsify the probe before trusting a clean run by injecting a declaration that cannot lose the cascade (`*{letter-spacing:4px !important}` must move every signature); an edit that shows zero deltas may simply have lost to a higher-specificity rule, which is a valid result, not a blind probe. Statistics cannot be judged on that instance at all: it ingests traffic, so even the _identical_ sheet moves signatures between loads, and a live delta is not evidence until the same drift reproduces with an unchanged stylesheet. Cascade neutrality is decided instead by the stubbed harness - `CSS_CANDIDATE=<file> npx vitest run test-node/ui/admin-ui-css-cascade.test.ts -t "candidate stylesheet"` compares signature multisets and per-(property,value) element counts over four viewport widths and nine states - and it is deterministic only with `page.clock` installed before `goto`, statistics stubs pinned to one overview payload (the fixture rotates three), auto refresh toggled off through `page.evaluate` because `#autoRefreshLogs` is visible only on the logs tab, dialogs digested after their settle markers (`#metricsRefresh`, then `#targetCheckModels`, enabled), and hover/focus cleared before each digest. When a value really changes, `CSS.getMatchedStylesForNode` names the winning rule and `rule.style.range.startLine` gives its source line; Vitest has no `it.setTimeout`, so pass the timeout as the third `it()` argument.
- Checking admin-UI layout without patching the UI test file: a throwaway Node script that imports `createAdminServer` + `loadAdminStaticAssets` from `dist-node` with a stub `logService`, opens the page with the Playwright-bundled Chromium and screenshots `.log-list` at several `--sidebar-w` values is much faster. `loadAdminStaticAssets` serves the built `dist-node/**/static` copies, so run `npm run build` after editing `src/admin/static` (otherwise the harness silently renders stale CSS); when only the static files changed and `dist-node` is already compiled, `node dist-node/scripts/copy_static_assets.js` alone is enough. Compare `line.scrollWidth` with the container width to detect clipping numerically. That probe cannot see line wrapping — a wrapped box keeps `scrollWidth === clientWidth` — so pair it with an element height or a looked-at screenshot. An element screenshot only covers the part inside the viewport, so a narrow-viewport capture of a tall card silently omits the section below the fold; screenshot the smaller inner element instead. Running a `.mts` UI probe through `npx tsx` transforms `page.evaluate` closures with a `__name` helper that does not exist in the browser (`ReferenceError: __name is not defined`): keep evaluated code free of named helpers, or drive the interaction with Playwright locators and leave the evaluate as a plain property read.
- Measure click-to-visible with in-page marks (a capture-phase click listener on `#logItems` plus a `MutationObserver` on the pane) and never with wall-clock around `page.click`: Playwright's own hover/stability/hit-target work is ~100 ms on a paged list and dwarfs the app. Wall-clock timings also lie when the pane already holds the previous record's rows - wait for the first pane mutation _after_ the click mark, not for `.json-row` to exist. Per-element `innerHTML` interception looks harmless but silently changes what the render path sees, so prefer "total render minus build/measure" for the assign cost. `const state` is a lexical global and never appears on `window` (only function declarations do, in a classic script), so a probe cannot read `state.jsonPaneHtml` - and `renderJsonPane(key, options)` takes an options object, so logging its second argument as "chars" prints `[object Object]`. The tree builder is `jsonRowHtml`, not `buildJsonTreeString`.
- A modal `<dialog>` (opened with `showModal()`) makes everything behind it inert, so a UI probe cannot click page controls such as `#languageSelect` while the dialog is open — drive the switch with `window.setLanguage("en")` from `page.evaluate` (function declarations in the classic `app.js` are reachable on `window`), and any dialog whose content is language-dependent must re-render from that path while it is open (the `if ($("metricsDialog")?.open) …` pattern). `page.addInitScript` serializes the function body, so a body that reads a Node-side closure variable silently never runs in the browser: a probe that ignores the language it asked for has an init-script bug, not a page bug — pass the value through Playwright's own second argument or inline the literal.
