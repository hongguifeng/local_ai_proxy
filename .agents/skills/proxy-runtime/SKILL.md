# Proxy runtime reload and response logging semantics

These traps were learned in this repository and moved here verbatim from `AGENTS.md`;
nothing was paraphrased.

- Config save no longer restarts a listener whose listen address and enabled flag are unchanged: `ProxyManager` routes such updated pairs to `ProxyRuntimeRegistry.reloadPair()`, which swaps `{ pipeline, activeRequests }` as one object on the live listener and drains the superseded generation (ADR-011). Replacing only the pipeline leaves `resources.activeRequests` on the superseded registry, so `diagnostics()` double-counts the old requests and never sees the new ones - always swap both together. Traffic log services are cached per runtime entry by `resolved log_root + redact_logs`; reusing an instance also avoids `markPendingPricingInterrupted()` rewriting in-flight `pending` pricing rows. Verify the real save path (unit/UI tests do not cover in-flight semantics) by spawning `dist-node/src/main.js` in a throwaway cwd with `--port --config-file --log-root --application-config --no-browser`, opening an SSE request through the proxy port and `PUT /api/pairs` mid-stream: before the fix it returned ~2 s later on a new port with a `terminated` stream, now it returns in milliseconds on the same port with every chunk delivered.
- Upstream responses arrive compressed (`content-encoding: gzip`/`br`/`zstd`/`deflate`) because the client's `Accept-Encoding` is forwarded upstream and Node's `http` client does not decode it. The traffic log must store the DECODED body while the client keeps the encoded bytes verbatim (ADR-012, `src/proxy/response-decoder.ts` feeding `ResponseLogCapture`): a stored `{text, size_bytes}` body of U+FFFD replacement characters is the pre-fix shape, and those compressed bytes were destroyed by the UTF-8 decode at store time, so historical records are unrecoverable. Node 24 / undici does auto-decode all four encodings, so the client was never broken - only the log, the SSE observer (`first_token_ms`, `decode_window_ms`) and the usage capture.
- Encoding regressions are proven with a throwaway `.mts` at the repo root (deleted afterwards): `ProxyRequestPipeline` + a stub `TrafficLogWriter` + a fixture upstream. Compress per SSE event with `createGzip()` then `flush()` - without the flush a split compressed frame produces no output, so the first-token timing measures nothing and the test proves the wrong thing. Node's `http` client leaves `content-encoding` bodies encoded, so assert client-side passthrough by decompressing the received bytes in the test. The same harness against the user's real target (read the URL and API key out of `proxies.json`, never print them) proves the upstream's own framing decodes. In pipeline tests, wait on a promise resolved by the `request_finished` write: the client sees `end` before the pipeline logs it, so an array read straight after the client promise resolves is still empty.
