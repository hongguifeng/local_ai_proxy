# Acceptance against real upstreams without touching the user's instance

These traps were learned in this repository and moved here verbatim from `AGENTS.md`;
nothing was paraphrased.

- Real-upstream acceptance without touching the user's instance: rebuild the payload first (`npm run package:electron:dir`) — the shipped `release/win-unpacked` asar keeps the previous build's routes, so a stale artifact answers 404 for new endpoints and the whole verification proves nothing. Launch `release/win-unpacked/LLM Proxy.exe` with a throwaway `--application-config` holding a free admin port (`--port` sets the admin/UI port, not the proxy listen port, which comes from the pair config; the portable app config's admin port already belongs to the user's live instance), a throwaway pairs file whose members use an ABSOLUTE `log_root` — relative roots resolve against the application config file's directory, so a copied config writes straight into the user's `traffic.db` — fresh `LLM_PROXY_DATA_DIR`, `--log-root` only as a fallback, and `ELECTRON_RUN_AS_NODE` deleted. The throwaway config must set `admin.port`: a file that is `{}` or only carries `admin.host` makes the exe exit before it writes a single log line, so the run looks like a silent hang rather than a config error — measured on `release/win-unpacked`, where a config carrying `admin.port` served `/api/health` and `/api/logs` while the host-only and empty variants never bound a port at all. Never stop or kill a user service to simulate a dead node: point a group member at a port that was bound and then closed, which produces a real `ECONNREFUSED`. Tell your own processes apart by creation time and kill only those; with `psutil.process_iter` read `p.info['create_time']`, not `p.create_time`, which is a bound method and dies with `TypeError`.
- Toggling load balancing off to measure routing overhead confounds the number with engine contention, because every request then piles onto one default target: on two identical engines the median was _lower_ with the group on than off. Prove the hot path is memory-only by timing the status endpoint (~0.75 ms) and comparing metrics-on against metrics-off latency, and read a record's `request_meta.duration_ms` / `response_meta.first_token_ms` before blaming the API for late history — a 1.5 MB body is ~193k prompt tokens and 41 s of engine prefill, so visibility follows the response, not the body read.
- Whatever the summary/brief model must know has to be inside the model input: `prepareSummaryRequest` keeps only `model`/`messages`/`input`/`instructions`, so request headers (client identity) are invisible unless sent alongside — the task brief passes them as a separate `client` block. Real-model checks against the user's own config are cheap (the summary model is a local proxy port) and are the only way to prove a prompt change really extracts what it asks for.
- A smoke harness that blames the product usually has a wrong fixture, and the app is right while the harness is wrong. Target objects read `target_url`, not `upstream_url`: a misspelled key falls through `normalizeTargetConfig()` to `DEFAULT_TARGET_URL = http://127.0.0.1:1235` (`src/config/defaults.ts`), the proxy answers `502 Bad Gateway`, and the stored record's `response_meta.error` names the refused port — read that record before concluding anything. `Bad Gateway` is produced by `src/proxy/proxy-request-pipeline.ts` when the upstream call fails, so it is the application reporting, not the application failing. The summary endpoint rejects any payload without a `segments` array (`parseSummaryPayload` in `src/maintenance/log-query-service.ts`) with `summary_failed` and "did not return the expected JSON shape", so a fixture returning only `outcome`/`model_note` proves nothing about undeclared-key survival. Header redaction is gated by the target's `redact_logs` (default false; `src/logging/traffic-log-service.ts` reads it as `redactLogs` and only then runs `redactEvent`): a harness that asserts `[redacted]` without turning it on will read the client's real `authorization` back and call that a leak, while `strip_request_fields` only shapes the forwarded upstream request, never what is stored.
- The usage-statistics routes are not answerable without a window: `/api/usage-statistics/overview`, `trend`, `options` and `export` answer 400 when `from` and `to` are missing, so a probe that calls them bare reports a product failure that is only a missing query string. `test-node/admin/api-contract.test.ts` spells the exact shapes out in its `probeUrl` function - copy from there rather than inventing one.
- An unpriced record stores `cost_nano_cny` as NULL on purpose, so `typeof(cost_nano_cny)` on a fresh smoke database is `null` by design. Assert the declared column type with `PRAGMA table_info(records)` - `INTEGER` for the money column, `TEXT` for `request_body_json` - instead of the runtime type of a value that is legitimately absent.
