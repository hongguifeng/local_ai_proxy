# TODO workflow reference

## 1. 最小任务模板

```markdown
### TASK-XX：一句话任务名

- 状态：未开始
- 前置任务：无 / TASK-YY
- 入口：当前源码符号、当前合同、设计章节

- [ ] 先复现或核对当前行为：写出输入、夹具和预期观察。
- [ ] 实现最小变更：列出状态所有者、写入口和生命周期影响。
- [ ] 补充有意义的测试：每个关键拒绝、失效和成功路径至少有证明。
- [ ] 同步文档：只更新受影响的当前合同、设计或报告。

验收：写成用户或系统可观察的结果，避免“代码完成”这类不可验证表述。

验证：写出实际测试文件、命令和必要的隔离方式。

结果与限制：记录实际结果、版本/commit、未验证项和阻塞条件。
```

任务状态只在以下条件下转换：

| 当前状态 | 可以转为 | 条件                                               |
| -------- | -------- | -------------------------------------------------- |
| 未开始   | 进行中   | 前置任务完成，当前事实和入口已核对                 |
| 进行中   | 已完成   | 实现、测试、文档同步和验收全部有证据               |
| 进行中   | 阻塞     | 缺少外部依赖或证据，并写清解除条件                 |
| 阻塞     | 进行中   | 阻塞条件解除且已重新核对当前事实                   |
| 阻塞     | 已完成   | 只有阻塞项的验收条件已正式改为不适用，并有决策记录 |

## 2. 开始任务检查

- [ ] `AGENTS.md`、`docs/README.md`、`docs/current/architecture.md` 已阅读。
- [ ] 当前代码、测试和文档入口已搜索；历史文档只作为背景。
- [ ] 前置任务状态和当前任务状态一致。
- [ ] 已找到所有相关读入口、写入口、reload/stop、删除和重启路径。
- [ ] 已确认是否需要专项 skill、隔离 worktree、真实上游或 UI 基线。
- [ ] 已把未知、缺失、过期、零值和失败状态分开写入验收口径。

## 3. 阶段 checkpoint

长任务建议分成四个 checkpoint：

| checkpoint | 最小产物                          | 不能宣称的内容                  |
| ---------- | --------------------------------- | ------------------------------- |
| 实现       | 可构建代码和定向测试              | 全量通过、收益已证明            |
| 专项验证   | 相关测试、探针或浏览器证据        | 真实引擎收益，除非使用真实引擎  |
| 文档收口   | 当前合同、设计/计划状态和报告链接 | 仅凭文档宣称实现                |
| 交付验证   | portable、隔离 smoke、ABI 查询    | 把 smoke 当成性能或外部引擎证明 |

每个 checkpoint 都应留下提交或结果文件。恢复时先读取最后一个 checkpoint，再检查工作树和当前 HEAD，不从旧聊天总结推断文件状态。

## 4. 完成记录审查

完成记录必须能回答：

- 代码改变了哪个状态，状态由谁持有？
- 何时生效，哪些请求/回调/配置代仍使用旧状态？
- 删除、停用、reload、重启、超时、重复提交和迟到结果如何处理？
- 哪些字段或行为是当前合同，哪些只是建议、测量或历史结果？
- 哪条命令或测试证明每项验收，证明边界是什么？
- 哪些项仍缺真实依赖或独立实验，为什么不能用合成 fixture 替代？

如果答案只写“测试通过”“已经合并”或“没有问题”，记录仍未收口。
