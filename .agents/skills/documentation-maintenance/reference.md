# 文档维护参考

## 经验分级

| 证据强度                           | 记录方式                                                                | 例子                                              |
| ---------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------- |
| 单次观察，尚未复现                 | 当前任务记录或报告                                                      | 某次 CI 超时、一次上游不可用                      |
| 已复现，适用于一个明确工作流       | 对应 skill 的 `Invariants`、`Standard commands` 和 `Reading the result` | 打包后必须检查 `app.asar`，否则旧 bundle 可能残留 |
| 已由代码、测试或实测确认的当前合同 | `docs/current/`，必要时配套测试                                         | 配置保存复用监听器、历史数据库可读                |
| 存在替代方案和长期取舍             | ADR                                                                     | 选择 SQLite 驱动、响应体存储方式                  |
| 所有任务都必须知道的高代价边界     | `AGENTS.md`                                                             | 用户运行实例只读、ABI 切换顺序                    |

## 任务结束维护记录模板

```markdown
### 文档维护检查

- 触发事实：<文件、符号、命令、错误或实测行为>
- 证据：<复现命令、测试、日志或代码路径>
- 归属：<AGENTS / skill / current / ADR / report / plan>
- 更新：<修改的文件和规则>
- 失效条件：<何时需要重新验证或删除>
- 验证：<运行的检查和结果>
```

不需要为了填模板而新增文档。把这段记录放在当前任务的计划、报告或提交说明中，只有跨任务价值已经明确时才提取到长期文档。

## 过期描述的归属检查

发现某段叙述已经与代码、测试或实测不一致时，动笔前逐项回答：

- 这段叙述现在还是真的吗？以代码、测试或实测为准，不以另一份文档为准。
- 目标文件的 `状态`、`权威性`、`更新条件` 允许原地改写吗？`current/`、进行中的设计与计划，以及声明“当前代码不一致时先更新设计或明确偏差”的已接受设计可以；归档计划、报告和历史材料不行。
- 同一事实是不是已经在当前合同、README 和设计里各写了一遍？只留一个权威入口，其余链接过去。
- 追加一段会不会让同一文件同时留着新旧两种说法？会，就原地改写，不追加。
- 改写后中文正文是否只剩一种自然语言？代码符号、路径、命令和 HTTP 字段不算混用。

## AGENTS.md 提案检查

在根规则中增加内容前逐项回答：

- 这条规则是否与具体功能无关？
- 它是否跨多个未来任务有效？
- 遗漏它是否会触发数据损坏、用户实例影响、ABI 破坏、错误发布或大量返工？
- 是否能在一两句话内说明动作和验证入口？
- 详细步骤是否已经放在对应 skill，而不是复制到 AGENTS？

有一项回答为“否”时，优先放入 skill、当前合同、ADR 或报告。

## Skill 提案检查

新增或扩展 skill 时，必须能从 frontmatter 的 `description` 判断使用时机，并在正文回答：

- 什么时候触发；
- 运行期间哪些事实不能破坏；
- 标准命令是什么；
- 什么结果表示通过、失败或需要继续调查；
- 细节和权威材料在哪里。

命令必须来自 `package.json` 或现有工具，链接必须指向当前文件。涉及 Windows、Electron、数据库或用户实例时，先复核 `AGENTS.md` 的边界。

## 删除或降级规则

一条规则满足以下任一条件时才能删除或降级：

- 所依赖的代码、脚本、路径或工具已经删除，并且仓库搜索确认没有替代入口；
- 自动测试、构建配置或工具行为已经让该错误不可能发生；
- 当前实现、测试和运行记录共同证明原事实已经过期；
- 它只描述一次性的历史结果，应迁移到报告或历史目录。

删除后重新搜索所有引用，运行 `npm run check:skills`，并在变更说明中记录删除依据。
